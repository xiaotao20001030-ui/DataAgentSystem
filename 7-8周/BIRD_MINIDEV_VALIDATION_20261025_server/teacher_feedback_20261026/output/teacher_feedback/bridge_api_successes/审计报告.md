# API 隐藏桥接表实验：18 个执行成功案例审计

已逐条读取 SQL，并通过 SQLite authorizer 的 EXPLAIN 记录实际访问的表和列；同时复跑预测和 gold，复现全部 18 个集合匹配成功。所有数据库以只读方式打开。

原分母：103 个变体，4 个 gold 不可评分；18/99=18.18%。以下结果说明这 18 个成功的来源。

| 来源           | 数量 | 占 18 个成功 |

在 SQL 准备阶段禁止读取隐藏表，11 条被拒绝，剩余 7 条；进一步禁止读取任何提示词未提供的表或列，4 条额外被拒绝，仅 3 条通过。因此，“遵守可见 schema 且结果集合匹配”的成功率是 3/99=3.03%，它仍不能等同于语义正确率。

## 3 个只使用可见 schema 的案例

- q260：原子表和键表共享 molecule_id，可绕过 molecule；当前匹配原子只有一个三键，IN 与 gold 的连接计数一致。若同分子增加另一个三键，gold 可能重复计数，因此不能宣称通用等价。
- q263：直接按 molecule_id 连接 atom 与 bond。诊断确认 molecule_id 唯一，atom 和 bond 均无找不到 molecule 的记录，所以当前数据中省略 molecule 不改变结果。
- q149：错误连接账户 ID 与地区 ID。gold 返回 461 行 DISPONENT，预测 DISTINCT 返回 1 行 DISPONENT；结果集合相同，但筛选的账户并不相同。这是低信息输出造成的集合匹配假阳性，不能视为有效替代路径。

q637 同样因去重而匹配：预测 2 行、gold 5 行，唯一值同为 `<books>` 与 NULL。现有评分采用集合语义，这符合原评分规则；它不能证明查询在语义上等价。

## question / evidence 是否泄露隐藏表名

只有 q981 的 qualifying 与 q149 的 account 在 question/evidence 中出现完整同名词，均为自然语言用词；未发现这 18 条 evidence 以 `隐藏表.列名` 的形式直接写出隐藏表标识。多条 evidence 保留了隐藏列名，例如 q895 的 milliseconds、q933 的 positionOrder、q772 的颜色列名。

SQL 访问记录能够证明模型引用了未提供的 schema；它无法区分模型是从语义线索推断、猜测还是已有知识中恢复了表名。不能将全部 11 条直接归因于记忆或某种确定的“泄漏”机制。

## 可用于修订报告的表述

> missing_bridge_table 条件仅从提示 schema 隐藏表，原数据库保留全部数据。API 在 99 个可评分变体中有 18 个结果集合匹配成功。其中 11 个读取隐藏桥接表，4 个使用其他未提供的表或列，只有 3 个完全遵守可见 schema；这 3 个中又有 1 个明显错误连接因输出值重复而被判对。因此 18.18% 体现的是完整数据库上的执行集合匹配成功率，不能直接解释为在严格 schema 缺失约束下的推理成功率。

建议保留原执行指标，另报 schema 合规指标与误匹配案例。先对预测加 SQLite 访问限制即可验证这些失败，不需要为此次核查物理删除源数据库表。

### q1028 — european_football_2

问题：In Scotland Premier League, which away team won the most during the 2010 season?

Evidence：Final result should return the Team.team_long_name; Scotland Premier League refers to League.name = 'Scotland Premier League'; away team refers to away_team_api_id; away team that won the most refers to MAX(SUBTRACT(away_team_goal, home_team_goal) > 0); 2010 season refers to season = '2009/2010'; won the most refers to MAX(COUNT(*));

隐藏表：match；类型：读取隐藏桥接表

预测：

```sql
SELECT t.team_long_name
FROM (
    SELECT m.away_team_api_id AS team_id, COUNT(*) AS wins
    FROM Match m
    JOIN League l ON m.league_id = l.id
    WHERE l.name = 'Scotland Premier League'
      AND m.season = '2009/2010'
      AND m.away_team_goal > m.home_team_goal
    GROUP BY m.away_team_api_id
    ORDER BY wins DESC
    LIMIT 1`
) w
JOIN Team t ON t.team_api_id = w.team_id;
```

Gold：

```sql
SELECT teamInfo.team_long_name FROM League AS leagueData INNER JOIN Match AS matchData ON leagueData.id = matchData.league_id INNER JOIN Team AS teamInfo ON matchData.away_team_api_id = teamInfo.team_api_id WHERE leagueData.name = 'Scotland Premier League' AND matchData.season = '2009/2010' AND matchData.away_team_goal - matchData.home_team_goal > 0 GROUP BY matchData.away_team_api_id ORDER BY COUNT(*) DESC LIMIT 1
```

实际读取：league, match, team。

预测行数 / 唯一行数：1 / 1；gold：1 / 1。

隐藏表禁读检查：access to Match.away_team_api_id is prohibited；仅可见 schema 检查：access to Match.away_team_api_id is prohibited。

Evidence：eyes refers to eye_colour_id; hair refers to hair_colour_id; skin colour refers to skin_colour_id; female superheroes refers to gender = 'Female'; published by Dark Horse Comics refers to publisher_name = 'Dark Horse Comics';

隐藏表：superhero；类型：读取隐藏桥接表

预测：

```sql
SELECT superhero.eye_colour_id, superhero.hair_colour_id, superhero.skin_colour_id
FROM superhero
JOIN gender ON superhero.gender_id = gender.id
JOIN publisher ON superhero.publisher_id = publisher.id
WHERE gender.gender = 'Female'
  AND publisher.publisher_name = 'Dark Horse Comics';
```

Gold：

```sql
SELECT T1.eye_colour_id, T1.hair_colour_id, T1.skin_colour_id FROM superhero AS T1 INNER JOIN publisher AS T2 ON T2.id = T1.publisher_id INNER JOIN gender AS T3 ON T3.id = T1.gender_id WHERE T2.publisher_name = 'Dark Horse Comics' AND T3.gender = 'Female'
```

实际读取：gender, publisher, superhero。

预测行数 / 唯一行数：5 / 5；gold：5 / 5。

隐藏表禁读检查：access to superhero.eye_colour_id is prohibited；仅可见 schema 检查：access to superhero.eye_colour_id is prohibited。

直接读取隐藏 superhero 表，返回五行颜色 ID；evidence 给出三种颜色列名。

### q775 — superhero

```sql
SELECT (SUM(CASE WHEN colour.colour = 'Blue' AND gender.gender = 'Female' THEN 1 ELSE 0 END) * 100.0) / NULLIF(SUM(CASE WHEN gender.gender = 'Female' THEN 1 ELSE 0 END), 0) FROM superhero LEFT JOIN colour ON superhero.skin_colour_id = colour.id LEFT JOIN gender ON superhero.gender_id = gender.id;
```

### q263 — toxicology

问题：What is the composition of element chlorine in percentage among the single bond molecules?

Evidence：element chlorine refers to element = 'cl'; single bond refers to bond_type = '-'; percentage = DIVIDE(SUM(element = 'cl'), COUNT(atom_id)) as percent where bond_type = '-'

隐藏表：molecule；类型：只使用可见 schema

预测：

```sql
SELECT SUM(CASE WHEN T1.element = 'cl' THEN 1 ELSE 0 END) * 100.0 / COUNT(T1.atom_id) AS percent FROM atom AS T1 INNER JOIN bond AS T2 ON T1.molecule_id = T2.molecule_id WHERE T2.bond_type = '-';
```

Gold：

```sql
SELECT CAST(COUNT(CASE WHEN T.element = 'cl' THEN T.atom_id ELSE NULL END) AS REAL) * 100 / COUNT(T.atom_id) FROM ( SELECT T1.atom_id, T1.element FROM atom AS T1 INNER JOIN molecule AS T2 ON T1.molecule_id = T2.molecule_id INNER JOIN bond AS T3 ON T2.molecule_id = T3.molecule_id WHERE T3.bond_type = '-' ) AS T
```

实际读取：atom, bond。

预测行数 / 唯一行数：1 / 1；gold：1 / 1。

隐藏表禁读检查：通过；仅可见 schema 检查：通过。

只用可见列，直接连接 atom 与 bond，省去 molecule；当前 molecule_id 唯一且无孤儿记录，因此冗余桥接表可被省去，比例均为约 2.684%。

### q149 — financial

问题：Please list the account types that are not eligible for loans, and the average income of residents in the district where the account is located exceeds $8000 but is no more than $9000.

隐藏表：account；类型：只使用可见 schema

预测：

```sql
SELECT DISTINCT d.type
FROM disp AS d
JOIN district AS di ON d.account_id = di.district_id
WHERE d.type <> 'OWNER'
  AND di.A11 > 8000
  AND di.A11 <= 9000;
```

Gold：

```sql
SELECT T3.type FROM district AS T1 INNER JOIN account AS T2 ON T1.district_id = T2.district_id INNER JOIN disp AS T3 ON T2.account_id = T3.account_id WHERE T3.type != 'OWNER' AND T1.A11 BETWEEN 8000 AND 9000
```

实际读取：disp, district。

预测行数 / 唯一行数：1 / 1；gold：461 / 1。

隐藏表禁读检查：通过；仅可见 schema 检查：通过。

只用可见列，但错误地令 disp.account_id=district.district_id，跳过实际账户所属地区。预测 DISTINCT 仅返回 DISPONENT；gold 461 行也全为 DISPONENT，因此集合评分判对。
