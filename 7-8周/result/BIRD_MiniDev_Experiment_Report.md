# BIRD Mini-Dev 验证性实验报告

*小模型 Schema 鲁棒性与向量检索桥接偏差*

实验日期：2026 年 10 月 21 日

数据规模：BIRD Mini-Dev SQLite，500 道题，11 个数据库

实验定位：探索性验证与后续确认性实验设计

# 执行摘要

本实验在 BIRD Mini-Dev 的 500 道题上，以 gold SQL 所需的表和列为基线 schema，系统考察四个本地小模型与一个 API 大模型在多给列和漏给 schema 成分下的鲁棒性，并独立统计向量检索对桥接成分的漏选偏差。

检索部分结论明确：在 k=10 时，桥接成分并集漏选率比单表目标列高 28.17 个百分点，95% 置信区间为 [20.58, 35.65]，检索门槛通过。

执行部分未通过原始预注册门槛：随机加 20 列时，四个小模型相对 DeepSeek 的准确率下降差均未达到 10 个百分点；合成近义列条件下 DeepSeek 自身下降更大。

进一步分析发现，全体准确率下降受 baseline floor effect 影响。在双方 baseline 都正确的共同问题上，小模型加列后的保持率显著低于 DeepSeek。因此，原门槛不通过不能被解释为机制假设被否定。

漏给补充实验已完成。移除桥接表后五个模型普通执行准确率为 0.00%–19.42%，移除外键列后为 1.62%–35.02%。DeepSeek 的普通准确率明显更高，但其外键正确预测中有 162/173 仍读取了已从 schema 移除的列。改用合规准确率后，模型间大部分优势消失，说明原始执行准确率会高估信息缺失条件下的合规恢复能力。

最终判定：BIRD 实验作为探索性证据使用；原预注册门槛记录为不通过；下一步进入 Spider 2.0-Lite，并使用预先固定的 baseline-correct 保持率主指标复验。

# 1 研究问题与假设

- RQ1：加入无关列后，小模型执行准确率是否比 API 大模型下降更多？
- RQ2：向量检索是否更容易漏掉多表问题中的桥接表和外键/连接列？
- RQ3：检索桥接偏差与模型执行退化是否共同指向 schema linking 是主要失败环节？

原验证假设为：小模型在加入 20 个无关列时的执行准确率下降，比 API 大模型至少多 10 个百分点；同时，向量检索对桥接成分的漏选率显著高于单表目标列。两个条件必须同时成立。

# 3 实验设计

## 3.1 基线 Schema

使用 sqlglot 解析 gold SQL，提取真实表、显式列、连接边和 join 键。基线 schema 仅保留 gold SQL 所需的表与列。500 条基线均通过 schema qualification，确认没有漏掉物理表或列。

## 3.2 多给列扰动

构造 add_random_5/10/20/50 和 add_synonym_5/10/20/50 共八个条件，每个条件严格 500 条。

- 随机列从全库未被 gold SQL 使用的列中采样，因此也可能同时引入新表；`add_random_20` 有 494/500 个变体至少新增一张表。候选不足时补充中性合成列并标记 generated=true；50 列条件中合成列占 17.5%，并非极少数。
- 同名近义列包含其他必需表中的同名列和基于列名词法生成的近义列，均标记 generated=true。
- 所有新增列只改变模型看到的 schema 元数据，不物理修改 SQLite 数据库。
- 额外构造 427 题全真实 schema 近义列敏感性版本，generated=0；73 题因候选不足被排除。

## 3.3 漏给扰动

在 gold join 图上识别桥接表，并优先删除显式外键侧；没有声明外键时，回退到关键 join 列并标记 declared_foreign_key=false。共生成 missing_bridge_table 103 条、missing_fk_column 494 条。

103 和 494 个移除变体均由五个模型完成预测与评分，共 5 × 597 = 2,985 条。扰动只从 prompt 的 schema 中移除表和列，SQLite 物理数据库保持不变。因此除普通执行准确率外，还使用 SQLite authorizer 在 EXPLAIN 编译阶段记录预测实际读取的物理表和列，检查其是否读取了已移除对象。

## 3.4 执行评分

预测 SQL 与 gold SQL 均在只读 SQLite 连接中执行。正式评分严格采用 BIRD Mini-Dev 官方 evaluation_ex.py 的集合语义： set(predicted_rows) == set(gold_rows)，因此忽略行顺序和重复行。模型 SQL 与 gold SQL 均使用官方默认 30 秒超时；查询或 gold 执行错误按官方规则计为 incorrect，并在逐条结果中保留错误信息。

## 3.5 向量检索

使用 sentence-transformers/all-MiniLM-L6-v2 对完整数据库列进行编码，主分析 k=10，并报告 k=5/10/20/50。比较单表目标列、桥接表内列、外键/关键连接列及桥接成分并集。置信区间由按问题聚类的 10,000 次 bootstrap 得到。

# 4 数据审计

原始扰动文件共 5097 条唯一 variant_id；base 与八个多给条件均为 500 条，每个变体的 added 数量、schema 列数、gold 列保留和列唯一性检查均通过。

服务器文件 SHA-256 为 b1271267ebb3dcd4af584127422108f9eec304cbfd9ce150f998bbc04eb364e5，与本地原始版本一致。

并发运行期间，Qwen3-0.6B 和 DeepSeek 曾出现重复写入；最终均按 variant_id 去重。五个 5/10/50 新增预测文件最终均为 3000 条唯一记录，六个新增条件各 500 条。

独立 gold 审计中，500 条 gold SQL 有 498 条在 30 秒内完成，2 条超时。早期自定义评分器采用 Counter 并在部分 ORDER BY 条件下强制顺序，与官方语义不一致。正式结果已使用官方集合语义重新评分全部 27,620 条预测；旧分数仅保留用于差异审计，不再用于论文数字。

# 7 讨论

- 扰动类型比列数更重要。随机列的曲线总体平缓；合成近义列在 5 列时即触发明显失败并快速饱和。
- 全体准确率下降受 baseline 能力限制。Qwen3-0.6B 的 baseline 为 14.60%，绝对下降空间有限，原 10 pp 门槛存在结构性偏向。
- Baseline-correct 分析显示，小模型在原本会做的题上对 schema 干扰更脆弱，支持模型规模影响 schema linking 稳健性的解释。
- DeepSeek 在合成近义列下同样大幅下降，说明人工近义列对高级模型也有很强干扰；真实 schema 敏感性实验将这部分效应缩小到 6.32 pp。
- 检索层面已经确认桥接成分更难被召回；但本实验没有直接建立逐题“检索漏选导致执行失败”的因果中介模型。
- 漏给实验中，DeepSeek 的普通执行准确率显著高于本地小模型，但大部分正确预测仍读取了被隐藏的连接列；合规准确率在五个模型上均很低。
- 因此，漏给结果支持“连接 schema 成分缺失会造成严重退化”，但不支持“大模型能在完全不使用缺失成分时稳定恢复”的强结论。

# 9 结论与决策

| 判定项 | 结论 |
| --- | --- |
| 检索桥接成分漏选显著更高 | 通过 |
| 小模型全体执行准确率下降比 DeepSeek 多 10 pp | 不通过 |
| 6.1 原始综合通过标准 | 不通过 |
| Baseline-correct 机制证据 | 支持假设，但为事后分析 |
| 真实 schema 近义列敏感性 | 支持机制，外部效度更高 |
| 漏给普通执行准确率 | DeepSeek 明显更高，小模型接近地板 |
| 漏给合规恢复能力 | 五个模型均很低，模型规模优势不稳健 |

严格结论：BIRD Mini-Dev 上的原预注册执行门槛没有通过，因此不能直接宣称小模型在无关列下显著比大模型更脆弱。

机制结论：在 baseline 可解问题与真实 schema 近义列条件下，小模型保持率显著更低，说明原假设仍具有可信的机制支持。漏给条件下，DeepSeek 的优势主要来自读取或恢复被隐藏的连接列；当要求严格合规时，该优势基本消失，所有模型都很难恢复。

决策：按照原计划，不基于 BIRD 结果直接确认完整研究假设；进入 Spider 2.0-Lite SQLite，使用预先固定的 baseline-correct 主指标复验。

# 11 事后重分析（2026-10-22）

本报告完成后又做了一轮不重跑模型的事后审计，详见
`result/POSTHOC_REANALYSIS_2026-10-22.md`。其中三项会改变解释方式：

1. 原“桥接成分并集漏选率 +28.17pp”对比的是单表题目标列与多表题桥接列；
   加入“多表题非桥接目标列”基线后，桥接表内列反而更容易召回
   （-13.91pp，95% CI [-24.22, -3.69]），只有外键/join 列仍显著更难
   （+13.75pp，95% CI [+9.79, +17.73]）。
2. 原 `add_random_*` 实际同时加入新表（20 列时 494/500 个变体至少新增一张表，
   58.9% 的新增列来自新表），不能解释为“无关列”效应。
3. 原 `add_synonym_5` 中 63.5% 的新增列是 `same_name`，不是纯词法近义列；
   在 5 列条件内，`same_name=0` 时 Qwen3-4B/DeepSeek 准确率为
   59.30%/74.42%，出现 2 个以上同名干扰后降到 8–20%，断崖主要由同名造成。

4. 缺失 schema 的“合规准确率”分母是 authorizer 成功分析的子集
   （DeepSeek bridge 9/81、FK 11/446），不是全部变体，也不是 base-correct；
   应改名为“合规可评估子集上的合规率”。40/494 外键变体、9/103 桥接变体的
   evidence 出现被移除名字，需做剔除敏感性分析。
5. 执行门槛按 `question_id` 对齐后，四个随机 20 列差值的 95% CI 上界最高
   为 +5.2pp；因此可以更精确地写“数据排除了 +10pp 的下降差”，而不仅是
   “未达到 10pp”。
6. 纯列 20 补实验（只加列、不加表）已完成：全体准确率门槛仍不通过
   （四个下降差为 +0.60/+4.60/+1.80/-3.80pp，CI 上界均 <10pp）；
   但 baseline-correct 额外失败仍为 +32.35/+34.13/+20.51/+10.00pp，
   机制证据保留。因此原门槛失败不是“加表”造成的假象。

原预注册门槛“不通过”的判定不变；新增的 `add_pure_column` 条件用于补做
“只加列、不加表”的最小证实实验。
