# BIRD Mini-Dev 验证性实验报告（v2）

小模型 Schema 鲁棒性与向量检索外键偏差

原始实验日期：2026-10-21  
事后重分析与纯列补实验：2026-10-22  
数据规模：BIRD Mini-Dev SQLite，500 道题，11 个数据库  
实验定位：探索性验证、事后重分析与下一阶段确认性实验设计

## 版本说明

v1 报告记录了原始预注册门槛和正式评分。v2 不改变 v1 的历史判定，
而是把 2026-10-22 的事后审计与纯列补实验整合进正文：

1. 原“桥接成分”检索结论收窄为“外键/join 列偏差”；
2. 说明原 `add_random_*` 同时引入了新表，`add_synonym_*` 的 5 列断崖
   主要由 `same_name` 造成；
3. 补充“只加列、不加表”的纯列 20 实验；
4. 修正缺失 schema 的合规分母与 evidence 泄漏问题；
5. 保留原预注册门槛“不通过”的判定，不把事后分析写成确认性结果。

# 执行摘要

本实验在 BIRD Mini-Dev 的 500 道题上，以 gold SQL 所需的表和列为基线，
考察四个本地小模型与一个 API 大模型在 schema 多给、漏给和检索条件下的
鲁棒性。

核心结论：

- **检索预注册门槛通过，但结论必须收窄。** 原始 k=10 的“桥接成分并集”
  漏选率为 56.88%，比单表目标列高 28.17pp。加入“多表题非桥接目标列”
  基线后，桥接表内列反而低 13.91pp（95% CI [-24.22, -3.69]），
  只有外键/join 列高 13.75pp（95% CI [+9.79, +17.73]）。
  因此真正的检索偏差是**外键/连接列**，不是桥接表本身。
- **原预注册执行门槛不通过。** 随机加 20 列时，四个小模型相对 DeepSeek
  的下降差为 -2.20 到 +0.80pp，95% CI 上界最高 +5.2pp；
  数据可以排除“小模型多下降 10pp”的效应。
- **baseline-correct 分析支持机制，但属于事后条件分析。** 在双方 base
  都正确的题上，小模型在随机列条件下的额外失败为 25.98–34.48pp，
  真实 schema 近义列下为 17.35–30.63pp。
- **纯列 20 补实验仍不通过全体门槛，但机制保留。** 只加列、不加表时，
  四个下降差为 +0.60/+4.60/+1.80/-3.80pp，CI 上界均 <10pp；
  但 baseline-correct 额外失败仍为 +10.00 到 +34.13pp。
- **5 列近义断崖主要由同名干扰造成。** `same_name=0` 时 Qwen3-4B/
  DeepSeek 为 59.30%/74.42%；出现 2 个以上同名干扰后降到 8–20%。
- **漏给实验的普通准确率会高估合规恢复能力。** DeepSeek 外键正确预测中
  162/173 仍读取被移除列；合规分母是 authorizer 成功子集（9/81、11/446），
  不是全部变体或 base-correct。
- **最终判定不变：** BIRD 结果不足以确认原操作化假设；进入 Spider
  2.0-Lite 时应以预先固定的 baseline-correct 为主指标，并先做功效分析。

# 1 研究问题与假设

- RQ1：加入无关列后，小模型执行准确率是否比 API 大模型下降更多？
- RQ2：向量检索是否更容易漏掉多表问题中的桥接表和外键/连接列？
- RQ3：检索偏差与模型执行退化是否共同指向 schema linking 是主要失败环节？

原预注册假设：小模型在加入 20 个无关列时的执行准确率下降，比 API 大模型
至少多 10 个百分点；同时，向量检索对桥接成分的漏选率显著高于单表目标列。
两个条件必须同时成立。

v2 的澄清：

- RQ1 的原操作化指标（全体准确率下降差 ≥10pp）未通过；机制证据来自
  baseline-correct 条件分析，不能替代原门槛。
- RQ2 的“桥接成分”需拆成桥接表内列与外键/join 列；控制多表题后，
  只有后者稳健。
- RQ3 仍未被原实验识别：原执行实验使用 oracle gold schema，检索偏差是
  独立测量；若要检验因果链，需要额外的 retrieved-schema 执行条件。

# 3 实验设计

## 3.1 基线 Schema

使用 sqlglot 解析 gold SQL，提取真实表、显式列、连接边和 join 键。基线
schema 仅保留 gold SQL 所需的表与列。500 条基线均通过 schema qualification。

## 3.2 多给列扰动（v1）

构造 add_random_5/10/20/50 和 add_synonym_5/10/20/50 共八个条件，
每个条件严格 500 条。

- 随机列从全库未被 gold SQL 使用的列中采样。由于基线只含 gold tables，
  这会同时引入新表：`add_random_20` 有 494/500 个变体至少新增一张表，
  58.9% 的新增列来自新表；`add_random_5` 为 467/500、63.8%。
- 候选不足时补充中性合成列并标记 `generated=true`。`add_random_50` 的
  25,000 个新增列中有 4,387 个（17.5%）是合成列，并非“极少数”。
- 同名/近义列包含其他 base tables 的同名列和基于列名词法生成的近义列。
  `add_synonym_5` 的 2,500 个新增列中 1,588 个（63.5%）是 `same_name`；
  10 列为 39.9%，20 列为 21.7%，50 列为 8.7%。
- 所有新增列只改变模型看到的 schema 元数据，不物理修改 SQLite 数据库。

## 3.3 纯列补实验（v2）

为了隔离“列数”本身，新增 `add_pure_column` 条件：

- 所有新增列都属于 gold tables，**不新增任何表**；
- 20 列条件中 66.9% 是真实列，33.1% 是中性 filler；10 列为 82.6% 真实列，
  5 列为 90.0% 真实列；
- 五模型各完成 base + pure 20 共 1,000 条预测；
- 该条件不替代原 `add_random_*`，而是回答“只加列、不加表会怎样”。

## 3.4 漏给扰动

在 gold join 图上识别桥接表，并优先删除显式外键侧；没有声明外键时，回退到
关键 join 列并标记 `declared_foreign_key=false`。共生成
missing_bridge_table 103 条、missing_fk_column 494 条。

扰动只从 prompt 的 schema 中移除表和列，SQLite 物理数据库保持不变。
除普通执行准确率外，还使用 SQLite authorizer 在 EXPLAIN 编译阶段记录预测
实际读取的物理表和列。

## 3.5 执行评分

预测 SQL 与 gold SQL 均在只读 SQLite 连接中执行。正式评分严格采用 BIRD
Mini-Dev 官方 evaluation_ex.py 的集合语义：
`set(predicted_rows) == set(gold_rows)`，忽略行顺序和重复行。
模型 SQL 与 gold SQL 均使用官方默认 30 秒超时；执行错误按 incorrect 记录。

## 3.6 向量检索

使用 sentence-transformers/all-MiniLM-L6-v2。列文档包含表名、列名、类型和
主键标记；主分析使用 question-only，k=10，并报告 k=5/10/20/50。另报告
question+evidence 作为敏感性分析。

原始比较基线是单表题目标列。v2 增加：
`multi_nonbridge` = 多表题 gold 列中既不属于桥接表、也不属于 join/FK 的列。
该基线用于控制“单表题 vs 多表题”的题目类型混淆。

# 5 检索实验结果

## 5.1 原始预注册结果

主实验使用 question-only 检索，k=10。桥接表采用“表内任意一列进入 top-k
即命中”的表级口径；外键列、桥接表内列和单表目标列采用列级口径。

| 指标 | 漏选数 | 总数 | 漏选率 |
| --- | ---: | ---: | ---: |
| 单表目标列 | 60 | 209 | 28.71% |
| 桥接表（表级） | 17 | 103 | 16.50% |
| 桥接表内列 | 104 | 250 | 41.60% |
| 外键/关键连接列 | 564 | 975 | 57.85% |
| 桥接成分并集 | 587 | 1032 | 56.88% |

原报告的比较对象是单表目标列，因此“桥接成分并集 +28.17pp”同时包含了
多表题难度和列类型效应。

## 5.2 匹配基线（v2）

使用原脚本的文档构造与标签集合复算，绝对漏选率与 v1 完全一致。加入
`multi_nonbridge` 后，k=10：

| 类别 | 漏选率 |
| --- | ---: |
| 单表目标列 | 28.71% |
| 多表题非桥接目标列 | 47.45% |
| 桥接表内列 | 41.60% |
| 外键/join 列 | 57.85% |
| 桥接成分并集 | 56.88% |

按问题配对的 bootstrap：

| 比较 | 差值 | 95% CI |
| --- | ---: | --- |
| 桥接表内列 - 多表非桥接目标列 | -13.91 pp | [-24.22, -3.69] pp |
| 外键列 - 多表非桥接目标列 | +13.75 pp | [+9.79, +17.73] pp |
| 桥接成分并集 - 多表非桥接目标列 | +13.11 pp | [+9.16, +17.14] pp |

结论：控制多表题后，桥接表内列并不更难召回；显著更难的只有外键/join 列。
原 +28.17pp 主要是题目类型效应，不能解释为“桥接表偏差”。

## 5.3 question+evidence 敏感性

| 类别 | 漏选率 |
| --- | ---: |
| 单表目标列 | 20.57% |
| 多表题非桥接目标列 | 37.34% |
| 桥接表内列 | 43.60% |
| 外键/join 列 | 58.97% |
| 桥接成分并集 | 57.66% |

配对差值：桥接表内列 +2.15pp（95% CI [-7.96, +12.24]），
外键列 +26.11pp（95% CI [+22.15, +30.16]）。桥接表效应不稳健，
外键/join 效应在两种 query 下都稳健。

## 5.4 检索结论

检索预注册门槛按原指标仍为“通过”，但机制结论应改写为：
**向量检索对外键/join 列的漏选偏差显著；对桥接表本身的偏差不稳健。**
这比“桥接成分偏差”更精确，也更能指导 schema linking 的改进。

## 6.4 Baseline-correct 条件分析

| 模型 | 共同正确题数 | 随机列额外失败 | 95% CI | 近义列额外失败 | 95% CI |
| --- | ---: | ---: | --- | ---: | --- |
| Qwen3-0.6B | 69 | +31.88 pp | [+18.84, +43.48] | +36.23 pp | [+24.64, +47.83] |
| Qwen2.5-Coder-1.5B | 116 | +34.48 pp | [+24.14, +44.83] | +10.34 pp | [+0.00, +20.69] |
| Qwen3-1.7B | 127 | +25.98 pp | [+17.32, +34.65] | +14.17 pp | [+6.30, +22.83] |
| Qwen3-4B | 229 | +12.23 pp | [+6.55, +17.90] | +6.11 pp | [+1.31, +11.35] |

定义：额外失败率 = DeepSeek 在共同 base-correct 题上的扰动保持率 -

该分析支持机制假设，但属于看到总体准确率后进行的条件分析，不能替代原
预注册门槛；它也忽略了“原本错、扰动后对”的增益。

## 6.6 纯列 20 补实验（v2）

只加列、不加表，五模型 base + pure 20。纯列补实验的 base 由同一次运行重新
生成，和 v1 base 可能有 0.2pp 左右的 GPU 推理波动；比较在本次运行内配对，
不跨运行混用。

| 模型 | base | pure 20 | 下降 | 相对 DeepSeek 下降差 | 95% CI |
| --- | ---: | ---: | ---: | ---: | --- |
| Qwen3-0.6B | 14.60% | 9.60% | 5.00pp | +0.60pp | [-3.00, +4.20] |
| Qwen3-1.7B | 27.20% | 18.20% | 9.00pp | +4.60pp | [+0.20, +9.00] |
| Qwen3-4B | 50.60% | 44.40% | 6.20pp | +1.80pp | [-2.40, +6.00] |
| Qwen2.5-Coder-1.5B | 26.60% | 26.00% | 0.60pp | -3.80pp | [-8.20, +0.40] |
| DeepSeek | 68.60% | 64.20% | 4.40pp | 对照 | - |

**全体准确率门槛仍不通过**：四个 CI 上界都低于 10pp。但 baseline-correct
额外失败仍显著：Qwen3-0.6B +32.35pp [+20.59, +44.12]、
Qwen3-1.7B +34.13pp [+24.60, +43.65]、Qwen3-4B +10.00pp

因此，原门槛失败不是“加表”造成的假象；在只加列、不加表的条件下，机制

| Qwen2.5-Coder-1.5B | 移除外键列 | 50/494 | 10.12% | 50.54% | 1.26%（2/159） |
| DeepSeek | 移除桥接表 | 20/103 | 19.42% | 28.36% | 11.11%（9/81） |
| DeepSeek | 移除外键列 | 173/494 | 35.02% | 50.92% | 2.47%（11/446） |

关键修正：

- “合规率”的分母是 authorizer 成功执行合规分析的子集
  （`compliance_evaluated`），不是全部变体，也不是 base-correct。
  因此不能直接跨模型比较，也不能把它写成“合规准确率”而不注明分母。
- `SELECT *` 不是主要问题：五个模型合计只有 0–6 条预测使用 `SELECT *`。
- evidence 泄漏需要处理：40/494 外键变体、9/103 桥接变体的 evidence 中
  出现被移除名字。剔除后外键普通准确率：DeepSeek 33.26%（原 35.02%）、
  Qwen3-4B 18.06%（原 20.24%）、Qwen3-1.7B 7.27%、Qwen0.6B 1.54%。
- 普通准确率高估的是“合规恢复能力”，不是“任务结果恢复”。猜中隐藏列
  在 outcome 上也是一种恢复；论文中应区分 outcome robustness 与
  process compliance。

# 7 讨论

- **扰动类型比列数更重要。** 随机加表/加列影响温和；同名干扰在 5 列时
  就造成断崖；纯列 20 只造成 0.6–9.0pp 的总体下降。
- **全体准确率门槛受 baseline floor effect 影响。** Qwen3-0.6B baseline
  14.60%，绝对下降空间有限；原 10pp 门槛存在结构性偏向。
- **Baseline-correct 分析显示机制存在。** 小模型在原本会做的题上对 schema
  干扰更脆弱；纯列 20 复现了这一点（+10.00 到 +34.13pp）。
- **检索偏差是外键/join 列，不是桥接表。** 控制多表题后，桥接表内列不再
  更难；这与“连接键在向量空间中缺少语义”的解释一致。
- **合成近义列是强干扰，但不是真实 schema 的代表。** 5 列断崖主要来自
  `same_name`；真实近义列条件又混入了新表，不能单独归因于词法真实性。
- **漏给结果支持“连接 schema 成分缺失会造成严重退化”，但不支持“大模型
  能在完全不使用缺失成分时稳定恢复”的强结论。**
- **RQ3 仍未识别。** 原执行实验使用 oracle schema；检索偏差是独立测量。
  若要检验“检索漏选导致执行失败”，需要 retrieved-schema 执行条件。

# 8 有效性与局限

| 维度 | 风险或限制 | 当前处理 |
| --- | --- | --- |
| 内部效度 | baseline floor effect | 报告主门槛失败，并补充 baseline-correct |
| 内部效度 | `add_random_*` 同时加表 | v2 增加纯列条件；原始条件改称“跨表扩展” |
| 构念效度 | 合成近义列含大量 `same_name` | 按 `same_name` 分层；5 列断崖改写 |
| 构念效度 | 真实近义列仍主要加新表 | 报告 423/427 与 4 题 gold-only；不做强归因 |
| 统计效度 | gate 原代码未对齐 qid | v2 已按 question_id 对齐；CI 上界 <10pp |
| 统计效度 | 单次 greedy 推理 | 固定模型与 prompt；报告 bootstrap CI |
| 评测效度 | 官方 30 秒超时和重复行规则 | 严格采用官方 set 语义 |
| 构念效度 | schema 隐藏但数据库保留列 | authorizer 检查读取对象，报告普通/合规两种口径 |
| 构念效度 | 合规分母是 authorizer 子集 | 明确标注 `compliance_evaluated` |
| 构念效度 | evidence 可能泄漏被移除名字 | 报告泄漏数并做剔除敏感性分析 |
| 外部效度 | 仅一个 Mini-Dev 数据集 | 下一步 Spider 2.0-Lite |
| 外部效度 | 检索仅一个 MiniLM、两种 query | 结论限定为当前 setup；不外推到所有 retriever |
| 可复现性 | DeepSeek API 版本可能变化 | 记录模型别名和调用日期 |
| 完整性 | 桥接移除子集 base 正确数很低 | 报告地板效应和题目聚类 CI |

# 9 结论与决策

| 判定项 | 结论 |
| --- | --- |
| 检索桥接成分漏选显著更高（原指标） | 通过 |
| 控制多表题后桥接表内列更难 | 不成立（-13.91pp） |
| 外键/join 列更难召回 | 成立（+13.75pp） |
| 小模型全体执行准确率下降比 DeepSeek 多 10pp | 不通过；CI 可排除 +10pp |
| Baseline-correct 机制证据 | 支持假设，但为事后分析 |
| 纯列 20 全体门槛 | 不通过；CI 上界 <10pp |
| 纯列 20 baseline-correct | 支持机制（+10.00 到 +34.13pp） |
| 真实 schema 近义列敏感性 | 支持机制，但受 table placement 混淆 |
| 漏给普通执行准确率 | DeepSeek 明显更高，小模型接近地板 |
| 漏给合规恢复能力 | 五个模型均很低；大模型优势主要来自猜测隐藏列 |

严格结论：BIRD Mini-Dev 上的原预注册执行门槛没有通过，因此不能直接宣称
小模型在无关列下显著比大模型更脆弱。机制结论：在 baseline 可解问题、
纯列 20 和真实 schema 近义列条件下，小模型保持率显著更低，说明 schema
linking 稳健性仍是一个可信的机制解释。漏给条件下，DeepSeek 的优势主要
来自读取或恢复被隐藏的连接列；当要求严格合规时，该优势基本消失。

决策：按照原计划，不基于 BIRD 结果直接确认完整研究假设；进入 Spider
2.0-Lite SQLite，使用预先固定的 baseline-correct 主指标复验。
