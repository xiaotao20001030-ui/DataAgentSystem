# BIRD Mini-Dev 事后重分析

日期：2026-10-22  
对象：`BIRD_MiniDev_Experiment_Report` 与原始扰动/评分文件  
性质：不重跑模型的事后重分析；不改变原报告已记录的预注册判定。  
本地结果副本：`7-8周/BIRD_RESULTS/`（预测、官方评分、分析 JSON、日志）。

## 结论摘要

1. 原“桥接成分”检索结论需要收窄：在控制“多表题”这一因素后，桥接表内列并不比多表题的非桥接目标列更难召回；显著更难的只有外键/join 列。
2. 原 `add_random_*` 条件同时加入了新表，不能解释为“无关列”效应。
3. 原 `add_synonym_5` 主要是 `same_name` 列，不是纯词法近义列；“5 列断崖”需要按 `relation` 分层重写。
4. 原执行门槛的代码存在配对对齐问题；修复后结论方向不变，但应把“未达到 10pp”写成“数据可以排除 +10pp”。
5. 原缺失 schema 实验的“合规准确率”分母是 authorizer 成功子集；需改标签，并检查 `SELECT *` 与 evidence 泄漏。
6. 纯列 20 补实验已完成：全体准确率门槛仍不通过，但 baseline-correct 额外失败仍显著；原门槛失败不是“加表”造成的假象。

## 1. 检索：+28.17pp 主要是多表题难度，其次是外键列

原报告用“单表目标列”作基线，但桥接成分只出现在多表题。重分析加入
`multi_nonbridge`：多表题中既不属于桥接表、也不属于 join/FK 的目标列。
使用相同的 `all-MiniLM-L6-v2`、question-only、`table.column` 文档，k=10：

| 类别 | 漏选率 |
| --- | ---: |
| 单表目标列 | 28.71% |
| 多表题非桥接目标列 | 47.45% |
| 桥接表内列 | 41.60% |
| 外键/join 列 | 57.85% |
| 桥接成分并集 | 56.88% |

按问题配对的 bootstrap（k=10）：

| 比较 | 差值 | 95% CI |
| --- | ---: | --- |
| 桥接表内列 - 多表非桥接目标列 | -13.91 pp | [-24.22, -3.69] pp |
| 外键列 - 多表非桥接目标列 | +13.75 pp | [+9.79, +17.73] pp |
| 桥接成分并集 - 多表非桥接目标列 | +13.11 pp | [+9.16, +17.14] pp |

解读：原报告“桥接成分并集比单表目标列高 28.17pp”把题目类型效应和列类型
效应混在一起；控制多表题后，桥接表内列反而比非桥接目标列更容易召回
（-13.91pp），外键/join 列仍显著更难（+13.75pp）。

该结果由服务器上的原脚本 `evaluate_retrieval_bias.py` 的文档构造与标签
集合重算，绝对漏选率与原报告完全一致（单表 28.71%、桥接表内列 41.60%、
外键 57.85%、并集 56.88%）。本地另一套 `table.column` 复算方向一致，
但绝对数值不同，不作为主结果。

question+evidence 条件下，原报告绝对值为单表 20.57%、桥接表内列 43.60%、
外键 58.97%、并集 57.66%。匹配基线结果为：桥接表内列 - 多表非桥接目标列
**+2.15pp**，95% CI [-7.96, +12.24]（不显著）；外键列 **+26.11pp**，
95% CI [+22.15, +30.16]。也就是说，桥接表本身的偏差会随 query 变化，
外键/join 列的偏差在两种 query 下都稳健。

## 2. random 条件实际加了新表

从 `perturbations/output/mini_dev_perturbations.jsonl` 直接统计：

| 条件 | 至少新增一张表 | 新增列来自新表 |
| --- | ---: | ---: |
| `add_random_5` | 467 / 500 | 63.8% |
| `add_random_10` | 488 / 500 | 62.1% |
| `add_random_20` | 494 / 500 | 58.9% |
| `add_random_50` | 496 / 500 | 51.2% |

`add_random_50` 平均新增约 5 张表，基本接近整库 schema。原报告“随机列影响
温和”应改写为“额外表影响温和”；它不能回答“只加无关列会怎样”。

## 3. synonym 条件不是纯近义列

`add_synonym_*` 的新增列构成：

| 条件 | `same_name` | `synonym` | `same_name` 占比 |
| --- | ---: | ---: | ---: |
| 5 列 | 1588 | 912 | 63.5% |
| 10 列 | 1993 | 3007 | 39.9% |
| 20 列 | 2168 | 7832 | 21.7% |
| 50 列 | 2181 | 22819 | 8.7% |

5 列的断崖主要是同名跨表列/同表近名，而不是词法近义。按 `add_synonym_5`
内部再分层（Qwen3-4B / DeepSeek）：

| `same_name` 数 | n | Qwen3-4B | DeepSeek |
| ---: | ---: | ---: | ---: |
| 0 | 86 | 59.30% | 74.42% |
| 2 | 62 | 8.06% | 25.81% |
| 3 | 105 | 10.48% | 16.19% |
| 4 | 74 | 20.27% | 29.73% |
| 5 | 170 | 8.82% | 18.24% |

同样加入 5 列，没有 `same_name` 时 Qwen3-4B 仍有 59.3%，一旦出现 2 个以上
同名干扰就掉到 8–20%。因此“近义列 5 列断崖”应改写为“同名跨表干扰造成
断崖；纯词法近义的影响小得多”。

真实 schema 条件也存在表位置混淆：423/427 题引入新表，65.1% 的新增列在
新表里；合成条件则全部加在 base tables。因此“41.22pp → 6.32pp”不能全部
归因于“真实 vs 合成”。

## 4. 执行门槛代码修复

原 `analyze_execution_gate.py` 计算了 `common_ids` 却没有使用，bootstrap 直接
截断两个列表；若某条件有缺失记录，配对会错位。已修复为按 `question_id`
对齐，并新增：

- `p_one_sided_10pp`：检验“差值 ≤ 10pp”；
- `excludes_10pp_gap`：95% CI 上界是否低于 10pp；
- `passed_strict_10pp_ci`：95% CI 下界是否达到 10pp。

原报告四个随机 20 列差值的 95% CI 上界最高为 +5.2pp，因此在修复后仍可
更精确地写：**数据可以排除“小模型多下降 10pp”这一效应**，而不是仅说
“样本不够/未达到”。

## 5. baseline-correct 的定位

baseline-correct 是“双方 base 都正确”的条件子集分析，属于事后分析；
它忽略了“base 错、扰动后对”的增益。建议补 2×2 transition matrix，并把
estimand 写成条件效应；不要把它称为“机制证明”。它仍可作为进入 Spider
预注册主指标的依据。

## 6. 缺失 schema 实验的口径

- `合规准确率` 的分母既不是全部 103/494，也不是 base-correct，而是
  **authorizer 成功执行合规分析的子集**（`compliance_evaluated`）。
  DeepSeek bridge 为 9/81=11.11%，FK 为 11/446=2.47%；
  Qwen3-1.7B bridge 为 3/27=11.11%。因此该列应改名为
  “合规可评估子集上的合规率”，不能直接跨模型比较——各模型
  `compliance_evaluated` 差异很大（如 bridge：Qwen0.6B 14，DeepSeek 81）。
  若按全部变体作分母，DeepSeek bridge 为 9/103=8.74%，FK 为 11/494=2.23%。
- `SELECT *` 不是主要问题：五个模型合计只有 0–6 条预测使用 `SELECT *`。
- evidence 泄漏需要处理：40/494 外键变体、9/103 桥接变体的 evidence 中出现
  被移除名字；在正确预测中，DeepSeek 外键有 22 条、Qwen3-4B 有 18 条
  同时命中 evidence 泄漏。剔除这些变体后，外键普通准确率为：
  DeepSeek 33.26%（原 35.02%）、Qwen3-4B 18.06%（原 20.24%）、
  Qwen3-1.7B 7.27%（原 7.49%）、Qwen0.6B 1.54%（原 1.62%）。
  泄漏变体本身准确率更高（如 Qwen3-4B 45.0%），但不改变主结论；
  论文中应把剔除版本作为敏感性分析。
- “普通准确率高估恢复能力”只对“不使用隐藏信息的合规恢复”成立；
  对“任务结果恢复”而言，猜中隐藏列也是一种恢复。论文中应区分
  outcome robustness 与 process compliance。

## 7. 仍然成立的结论

- 原预注册执行门槛不通过；不能宣称原操作化假设得到确认。
- 随机/近义扰动确实会造成退化，但退化的来源需要按新增表、`same_name`、
  `synonym` 重新归因。
- 检索对外键/join 列的偏差稳健；桥接表本身的偏差不稳健。
- 缺失连接成分会造成严重退化；合规恢复在五个模型上都很低。
- BIRD 结果足以支撑 RQ1 的系统实证，但不足以支撑“检索漏选 → 执行失败”
  的因果中介结论。

## 8. 最小补实验：纯列 20 已跑完

新增 `perturbations/generate_pure_column.py`，生成只从 gold tables 采列的
`add_pure_column_20`（5/10/20 也已生成）。20 列条件中约 66.9% 是真实列，
33.1% 是中性 filler；5 列条件约 90% 是真实列。服务器上五个模型已跑完
`base` + `add_pure_column_20`，官方 set 语义评分结果如下：

| 模型 | base | pure 20 | 下降 | 相对 DeepSeek 的下降差 | 95% CI |
| --- | ---: | ---: | ---: | ---: | --- |
| Qwen3-0.6B | 14.60% | 9.60% | 5.00pp | +0.60pp | [-3.00, +4.20] |
| Qwen3-1.7B | 27.20% | 18.20% | 9.00pp | +4.60pp | [+0.20, +9.00] |
| Qwen3-4B | 50.60% | 44.40% | 6.20pp | +1.80pp | [-2.40, +6.00] |
| Qwen2.5-Coder-1.5B | 26.60% | 26.00% | 0.60pp | -3.80pp | [-8.20, +0.40] |
| DeepSeek | 68.60% | 64.20% | 4.40pp | 对照 | - |

**全体准确率门槛仍不通过**：四个模型的 95% CI 上界都低于 10pp。但
baseline-correct 额外失败仍显著：Qwen3-0.6B +32.35pp
[+20.59, +44.12]、Qwen3-1.7B +34.13pp [+24.60, +43.65]、
Qwen3-4B +10.00pp [+4.78, +15.65]、Coder +20.51pp
[+11.97, +29.06]。因此，原门槛失败不是“加表”造成的假象；在只加列、
不加表的条件下，机制仍然存在，但全体准确率门槛依然失败。

这补的是原 RQ1 的核心操纵，不需要重跑原始 27,620 条预测。若 RQ3 要立住，
再补 retrieved-schema 执行条件：`perturbations/generate_retrieved_schema.py`
可生成 top-10 检索 schema 变体（500 条，gold column recall 均值 54.6%），
运行命令见 `analysis/README.md`。

## 9. Spider 样本量提醒

按 BIRD 上各模型与 DeepSeek 的 base 准确率、并假设题目间独立粗略推算，
共同 base-correct 的期望题数为：

| 模型 | base acc | 50 题 | 135 题 |
| --- | ---: | ---: | ---: |
| Qwen3-0.6B | 14.60% | 5.0 | 13.4 |
| Qwen3-1.7B | 27.20% | 9.3 | 25.0 |
| Qwen3-4B | 50.40% | 17.2 | 46.4 |
| Qwen2.5-Coder-1.5B | 26.40% | 9.0 | 24.3 |

50 题和 135 题都达不到“每个模型共同 base-correct ≥30”的预实验门槛；
0.6B 需要约 300 题。Spider 前应先做功效分析，或从确认性门槛中去掉 0.6B，
不要把 50 题预实验当作主检验。
