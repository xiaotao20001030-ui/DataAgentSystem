# 第 5–6 周必读论文对比表

任务书将 SLM-SQL 与 MSc-SQL 放在同一条必读项中；本表拆成两篇论文，因此实际覆盖 7 篇论文。

本表根据各论文的摘要、方法、实验、结论和局限章节整理，属于对比表初稿；组会前仍需本人逐篇通读原文并核对关键结论。

| 论文 | 问题 | 方法 | 数据/实验 | 主要结果 | 基线 | 弱点 | 与本课题的区别 | 用途 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| BIRD (NeurIPS 2023 D&B, arXiv:2305.03111) | 真实数据库中脏值、外部知识和 SQL 效率未被已有 Text-to-SQL 基准覆盖。 | 提出大规模跨域基准，强调数据库值理解、evidence grounding 和效率，定义 EX/VES。 | 12,751 个问题-SQL 对，95 个数据库，33.4 GB；dev 1,534 条，Mini-Dev 500 条。 | GPT-4 54.89% EX，人类 92.96%；说明真实大库仍远未解决。 | T5 fine-tuning、ChatGPT、Claude-2、GPT-4；GPT-4 54.89% EX，人类 92.96%。 | 标注成本高，以 SQLite 为主，没有单独控制系统仍需要多少 schema，也未解决大 schema 的 token 预算。 | 本课题不提出新 parser，而是使用 BIRD 研究小模型在多给/漏给 schema 条件下的敏感性，并将 BIRD 作为主数据和机制实验平台。 | 主数据集与 RQ1 证据来源 |
| Spider 2.0 (ICLR 2025, arXiv:2411.07763) | 企业级工作流包含超大 schema、多 SQL 方言、项目代码库和多步数据库操作。 | 提出 632 个企业级任务及 agent 评测框架，并提供自包含的 Lite/Snow Text-to-SQL 子集。 | 632 个任务，平均 812 列；Lite 547 条，其中 SQLite 135 条。 | o1-preview 代码 agent 仅解决 21.3%，而 Spider 1.0 为 91.2%、BIRD 为 73.0%。 | 代码 agent 和 Text-to-SQL 模型；o1-preview agent 在 Spider 2.0 仅解决 21.3%，Spider 1.0 为 91.2%。 | 完整任务依赖代码库、云数据库和昂贵交互；公开 gold SQL 不完整，难以直接做严格列级监督。 | 本课题只使用 Lite SQLite 子集，刻意隔离大 schema 选择问题，不使用多步 agent，也不把云数据库成本引入验证实验。 | 大 schema 外部效度数据 |
| The Death of Schema Linking? (arXiv:2408.07702) | schema linking 可能漏掉必需列，但强模型是否仍需要先做 schema linking？ | 比较全 schema 与不同 precision/recall 的 linking；采用 augmentation、selection、correction，并迭代 fine-tune GPT-4o。 | BIRD；按数据库抽取 dev 10% 作为评测，训练样本 500；报告 BIRD 71.83% EX。 | 在完整 schema 可放入上下文时，ft:GPT-4o pipeline 达到 BIRD 71.83% EX。 | GPT-4o、GPT-4o-Mini、GPT-4-Turbo、Llama 3.1、DeepSeek Coder、Claude 3.5、Gemini 1.5 等 12 个模型。 | 核心结论限定在完整 schema 能放入上下文的强模型；没有系统研究 0.6B–4B、小 token 预算和桥接结构补全。 | 本课题直接检验小模型是否需要更保守的 schema selection，并把 token 成本、模型感知效价和连接图补全列为核心变量。 | 反方观点与 RQ1 动机 |
| RSL-SQL (arXiv:2411.00073) | schema linking 一方面减少噪声，另一方面可能漏掉必需列并破坏数据库结构完整性。 | 双向 schema linking、上下文增强、完整/简化 schema 双路生成与二选一、多轮自纠错。 | BIRD、Spider；GPT-4o 与 DeepSeek；strict recall 94%，平均输入列减少 83%。 | GPT-4o 在 BIRD 67.21% EX、Spider 87.9% EX；严格 schema recall 94%。 | DIN-SQL、DAIL-SQL、MAC-SQL、TA-SQL、E-SQL 等开源 Text-to-SQL 方法。 | 依赖复杂 prompt 流程和大模型生成能力；目标是高召回而非显式 token 预算，未学习下游小模型的边际效用。 | 本课题在固定 token 预算下预测目标小模型的边际收益，显式权衡 false positive 与 false negative，并用主外键图补全桥接成分。 | 强 schema-linking 基线与 RQ3 对照 |
| SLM-SQL (arXiv:2507.22478) | 0.5B–1.5B 小模型受逻辑推理能力限制，在 Text-to-SQL 上明显落后。 | 基于 SynSQL-2.5M 构造 Think/Merge 数据，使用 SFT、RL 和 Corrective Self-Consistency 进行后训练与推理。 | BIRD 与 Spider；Qwen2.5-Coder-0.5B/1.5B、Qwen3-0.6B、Llama-3.2-1B、DeepSeek-Coder-1.3B。 | BIRD dev：0.5B 56.87%、Qwen3-0.6B 59.52%、1.5B 67.08% EX。 | 原始模型、SFT、SFT+RL、CSC-SQL；BIRD 上 0.5B 56.87% EX，1.5B 67.08% EX。 | 明确不研究 schema linking、agent 或 pipeline；依赖大规模后训练与多次候选推理。 | 本课题不修改模型权重，而是在模型前处理阶段选择 schema；两者互补，可用 SLM-SQL checkpoint 检验 schema selector 的跨模型迁移。 | 小模型能力上界与模型族依据 |
| MSc-SQL (NAACL 2025, arXiv:2410.12916) | 小型开源模型单独生成 SQL 仍落后于 GPT-4，同时 API 模型存在隐私、延迟和成本问题。 | 采样多个候选 SQL，训练 critique model 同时比较 SQL、执行结果和元数据，选择最佳候选。 | BIRD 与 Spider；10B 以下开源模型及同规模模型集成。 | BIRD dev 65.6% EX，Spider test 84.7% EX，使用 7B/8B/9B 三个模型形成候选。 | SFT 小模型、self-consistency、DTS-SQL、CodeS 及其他开源与闭源系统。 | 增加多候选采样和 critique 推理管线；核心优化发生在 SQL 生成之后，没有解决前端 schema 信息过多或缺失。 | 本课题作用于 SQL 生成前的 schema selection，目标是在 token 预算内提高目标模型生成正确 SQL 的概率，可与 MSc-SQL 的候选批评阶段级联。 | 小模型 test-time baseline |
| AttnLink (arXiv:2608.00693) | 现有 schema linking 在语义建模、连续分数可控性和推理效率之间做取舍。 | 从 LLM generation-anchor attention 提取 schema relevance；AttnLink-U 无训练，AttnLink-S 用 set-mass 与 adaptive floor 监督，支持 temperature/top-p。 | Spider、BIRD、Spider2-SQLite；mAP 分别为 99.22%、95.95%、83.29%，并测试 9 组下游生成器设置。 | Qwen3.5-9B AttnLink-S 的 schema-linking mAP 为 99.22/95.95/83.29；下游 EX 在 7/9 设置最佳或并列最佳。 | embedding retriever、cross-encoder reranker、生成式 schema linker 和 attention probing 基线。 | 依赖白盒 LLM 的注意力、层/头选择和模型架构；主要输出相关性分数，没有直接学习特定小模型的 token 预算边际效用和描述粒度。 | 本课题以目标小模型的对数似然反馈训练模型感知效用预测器，并联合 token 预算、描述粒度和连接图补全；AttnLink 是直接强基线。 | 最新 schema-linking 强基线 |
